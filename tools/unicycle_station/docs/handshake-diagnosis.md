# 串口已打开，但没有数据 / VERSION_MISMATCH

文档核对：2026-09-07。下方会话/COM 号和修复测试是 2026-09-06 的历史证据；当前默认发行入口见 [上位机说明](../README.md)，完整握手见 [protocol.md](protocol.md)。

## 本次实测证据（2026-09-06）

最近的真实串口会话 `20260906_195554_320600` 和 `20260906_195735_964100` 中，PC 分别发送两次带 CRLF 的 `cfg:hello`，约 2 秒重试、约 4 秒超时。原始接收字节均为 **0**，没有收到 MCU 的版本拒绝应答。

旧版 PC 的 `_hello()` 把超时、取消以及实际不兼容都显示成 `VERSION_MISMATCH`，因此本次文字提示不能作为“车上固件版本不对”的证据。旧版还把空串口读取记录成空 raw 记录，记录条数不代表收到过数据。

当前源码双方格式一致：

```text
PC → MCU: cfg:hello,1\r\n
MCU → PC: rsp:1,ok,hello,1,tc264-cfg1-task1,63\n
```

PC 再读取 status 和 Schema。当前源码 hello 标识为 tc264-cfg1-task1；旧 tc264-cfg1 仍是兼容 cfg v1。不能从已有 ELF 的文件名或历史检查判断当前源码是否已构建、烧入并运行。

## 上位机修复

- RX 为 0 的超时显示 `NO_RX`，明确“无法判断固件版本”。
- 收到数据但没有匹配 hello 显示 `HANDSHAKE_TIMEOUT`；格式错误与实际协议不兼容另行区分。
- 断开、停车等取消握手不再报版本错误。
- 顶部区分“串口已打开”和“MCU 已确认”，显示累计 RX/TX 字节。
- 新增“重新握手”按钮，仅发配置读取请求；参数仍须完整握手/状态/Schema 才开放。
- 空读取不再作为接收包写入日志；新会话元数据附带串口设置和数据源类别。

源码启动脚本已使用修复后的代码。考虑旧 EXE 正在使用中，本次更新包放在 `dist/handshake-fix/EmbeddedStation/EmbeddedStation.exe`，不会强制关闭原上位机。退出旧程序后打开更新包，重新选择串口。

## 按证据排查链路

1. 确认新固件已下载，调试器已 Resume/Run，CPU0/CPU1 正常运行，车身屏幕已进入菜单。只有编译完成或调试器停在断点上不会建立通信。
2. 串口应属于实际连接 UART2 的设备。本机枚举到 `COM9: Infineon DAS JDS COM` 和 `COM3: USB 串行设备`。调试器枚举的 COM9 不能仅凭名字视为 UART2；当前固件没有初始化 UART0 调试输出。COM3 是否是配套无线模块仍需用户按实际硬件确认。
3. 两端均为 115200、8N1；PC 流控 none，ASCII、CRLF。无线模块还需确认两端供电和配对/通道一致。
4. MCU UART2 TX 为 P10_5，RX 为 P10_6。当前驱动还检查模块 RTS 输入 P10_2；**高电平时暂停全部上行发送**，该脚初始化带上拉。USB-TTL 只连 TX/RX/GND、没有适配这一流控条件，也可能表现为完全无上行。这与 PC 设置中的 RTS/CTS 开关不是同一层控制。
5. 不要因为收不到数据就强制关闭模块流控或启动电机。先确认所用无线/有线连接方式；有线适配应按确定的接线调整，不能盲目短接模块输出。

当前 MCU 即使 STOP / VOFA_OFF 也应约 10 Hz 发送 `stat`，握手后附加低频 `att`、`task` 和转换时的 `taskevt`；无需发车才能验证链路。只有 `run` 的完整运行遥测依赖运行模式。

## 如果使用调试器观察

在固定车体且不启动任何运行模式的条件下，查看已有计数即可区分方向：

| 观察项 | 能说明什么 |
|---|---|
| `g_control_uptime_ms` 是否递增 | CPU0 1 ms 调度是否运行 |
| `g_vofa_rx_bytes` 在点击重新握手后是否增加 | PC → MCU 下行是否到达 |
| `g_vofa_cmd_lines` / `g_vofa_cmd_last` | CPU0 前台是否收到完整命令 |
| P10_2 电平、`s_tx_head` / `s_tx_tail` | 模块流控是否持续阻止 MCU 上行 |

这些是诊断判据，不代表本次已经读取了车上变量。此次没有自动连接串口、发车、修改 MCU 参数或执行 ADS 构建。

验证：50 项 pytest 通过，修复版窗口 EXE 的 Mock 八页面验证通过、退出码 0；见 [handshake-release.json](handshake-release.json)。用户补充无线发送 TX / 接收 RX 灯持续闪烁，说明模块链路存在活动，但仍需核对上位机选中的 COM 口；不能据此认定 PC 已收到字节。

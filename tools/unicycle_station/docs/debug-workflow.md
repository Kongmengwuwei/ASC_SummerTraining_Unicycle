# 调试增强版使用说明 · 0.2

新版入口：`../dist/debug-workflow/EmbeddedStation/EmbeddedStation.exe`。所有程序文件仍位于独轮车项目的 `tools/unicycle_station` 下。分发时复制整个 `EmbeddedStation` 文件夹；原发行包和握手修复包保留。

## 姿态方向

在 **3D 姿态** 页面分别勾选 **Roll 反向 / Pitch 反向 / Yaw 反向**。新默认配置将 Roll、Pitch 反向，Yaw 保持原方向。已有工作区保留你的映射，需要时直接使用开关调整。开关、轴映射和视角可随工作区保存。

改变方向后会清除显示归零和平滑缓存。这里只改变模型显示，不改变原始角度、波形、车辆机械零点、控制参数或轨迹方向。逐轴转动车体确认映射后再使用“显示归零”。

## 任务状态与进入 / 退出

**任务与轨迹** 页面显示当前道路状态、是否正式 Run、环岛阶段、视觉年龄和质量、状态转换序号及 MCU 队列丢弃数。左表保留最近 500 条事件，使用 MCU 时间标记进入、退出及阶段变化；右侧显示相对轨迹。

| 状态码 | 含义 |
|---|---|
| 0 | 未知 |
| 1 / 2 / 3 | 直道 / 左弯 / 右弯 |
| 4 | 十字路口 |
| 5 / 6 | 左环岛 / 右环岛 |
| 7 / 8 | 坡道 / 斑马线 |
| 9 / 10 | 丢线 / 视觉数据过期 |
| 11 / 12 | 保持状态 / 等待视觉 |

环岛阶段沿用车端定义：0 空闲、1 入环、2 进环、3 沿环、4 环内、5 出环。道路观测和正式 Run 分开显示，停车观察也能检查视觉识别结果。

十字、环岛、坡道和斑马线直接来自现有元素状态机。普通直道/弯道是新增的诊断分类：有符号归一化视觉曲率正值为左弯，进入阈值 0.035、退出阈值 0.020，普通道路切换需要持续 150 ms。它不参与速度规划或控制决策，也不代表增加了新的元素识别算法。

超过 700 ms 未收到任务状态显示 STALE。MCU 时间复位会分段；队列丢弃及序号缺口明确提示，不补造缺失事件。初次连接显示“首次观测”，不声称知道连接前的完整运行历史。事件记录反映 CPU0 已接收的视觉结果，不能恢复 CPU1 尚未发布或 CPU0 未采样到的瞬时状态。

**车端需要更新源码构建并烧录后才有 task/taskevt。** 本轮按照要求没有进行 ADS 构建、烧录或实车验证。旧 cfg v1 固件仍可使用参数、波形和姿态功能，任务页面等待新帧；协议版本仍为 1，不会因为缺少任务帧锁定原有参数功能。

## 相对轨迹

现有数据具备轮速和航向，因此可做二维航迹推算。新版 task 帧提供同一 CPU0 快照内的 MCU 时间、航向和 C 轮速度；上位机按 MCU 时间、平均速度与中间航向积分，正式 Run 时累计。

- 新帧频率为 5 Hz；只有旧遥测时，使用 run 的轮速和 250 ms 内收到的姿态航向近时配对，界面明确标记误差较大。缺少新鲜航向则暂停估算。
- 采样间隔超过 500 ms、停止后重新运行、数据源切换会断开绘制，不推算缺失路段。
- “轨迹归零”清除当前估算。“航向反向 / 速度反向”独立于 3D 开关，改变后重新累计。方向须与实车编码器和姿态坐标校验。
- 轴单位统一为米，支持 CSV 导出；最多保留 30000 个绘制点。累计路程包含已经从绘图区淘汰的旧点；数据缺口期间的路程未知。

这是相对航迹，不是绝对定位或真实赛道地图。轮胎打滑、编码器每米计数误差、姿态漂移、坡面投影和 5 Hz 转弯采样都会引入误差；没有外部定位信息可用于长期校正。左右弯趋势和短段相对运动可用于辅助调试，不应用它衡量精确赛道几何。

## 波形与参数

实时波形新增多图联动、双光标测量和通信缺口断线。开启“多图联动”后时间窗口、暂停/跟随及时间轴联动；双光标显示 Δt、采样值与差值，悬停读数可查看其他通道。图上标注道路状态、参数修改、保护、停车、模式和试验开始，悬停标记读取详情。图表时间仍为 PC 接收时间，MCU 事件队列延迟可能使图上标记晚于左表的实际 MCU 时间。

参数表在实时更新当前值时保持编辑器、选择和滚动位置，收藏在参数页与工作台之间共享。±10% 微调从零值开始时使用最小步长，避免按了没有变化。写入和 Flash 权限仍由现有 MCU 确认流程约束。

调参工作台可按 Rate、Angle、回收/速度环筛选参数，波形按单位分组显示。选择环路仅影响页面，不切换车辆 Test 模式。Pitch 遥测仍缺少完整内环反馈和输出，页面不填充虚构通道。工作区保存环路选择、波形停靠布局、方向开关、收藏与故障截取设置。

串口设置保存设备 VID/PID、序列号或 USB 位置；同一设备 COM 号变化时可重新定位。匹配不到或出现多个候选会要求重新选端口，不自动探测其他设备或发送配置命令。

## 试验与故障片段

**试验与对比** 的“开始观察记录 / 结束观察记录”只记录数据，不启动车辆。默认自动记录开启时，进入 Balance、Run、Test 或 Jog 所在的运行区间自动创建试验；STOP 后保留 2 秒再结束，2 秒内恢复运行则继续当前试验。正式 Run 的对齐点另取 stat.run_active。

每个试验在原会话的 `trials/*.trial.json` 保存名称、备注、开始和结束时的 RAM/Flash 状态快照、固件、设备配置及时间区间。参数修改过程在原始会话中保留。复制试验时应一起复制所属会话的 frames.jsonl 与 session.json；孤立的 trial.json 不包含曲线。

载入 A/B 两次试验或日志，选择同一个通道，可按试验起点、Run 开始、首次参数修改对齐。显示起始参数差异和均值、RMS、峰峰值、最小/最大值，支持导出 JSON 摘要。绘图每通道保留约 12000 个点，统计使用所有有效采样点；缺少对齐事件时不强行对齐。加载和索引在后台完成，可以取消。

开启“故障自动截取”后，保护、任务事件缺失/丢弃，以及进入丢线/视觉过期状态会尝试截取前 10 秒、后 5 秒。文件位于原会话的 `captures/`，附配套 `.session.json`，可独立打开回放。触发间隔至少 2 秒，最多保留 8 个待截取请求，归档队列有上限；磁盘错误和队列满在试验页面提示。主动断开导致后段不足时元数据标记 `tail_complete=false`，不声称完整录得后 5 秒。
